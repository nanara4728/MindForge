**[ НАЗВАНИЕ ПРОЕКТА ]**

MindForge — веб-приложение для подготовки к проверочным работам по материалам пользователя с адаптивным подбором заданий.

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

При самостоятельной подготовке к проверочным работам школьники используют конспекты, параграфы и материалы преподавателя. Для подготовки необходимо не только повторить содержание, но и проверить понимание отдельных тем.

Предполагаемая проблема заключается в трудности самостоятельного определения пробелов: перечитывание не показывает, способен ли ученик применить знания, а правильный ответ может быть результатом угадывания. Составление проверочных заданий и подбор упражнений для повторения требуют дополнительных усилий.

MindForge позволит создавать тренировочные задания по загруженным материалам, учитывать правильность и уверенность ответов, предлагать дополнительные проверки и сохранять результаты подготовки. Ученик сможет видеть, почему ему предложено следующее упражнение, и обращаться к соответствующему фрагменту источника.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

Приложение ориентировано на учащихся 5–11 классов, самостоятельно готовящихся по текстовым учебным материалам.

Выделяются следующие группы:

- **Учащиеся 5–7 классов:** нуждаются в понятных формулировках, небольших тренировках и простом интерфейсе.
- **Учащиеся 8–9 классов:** готовятся по более объёмным материалам и нуждаются в определении тем для повторения.
- **Учащиеся 10–11 классов:** заинтересованы в самостоятельном планировании повторения и отслеживании результатов по нескольким материалам.



**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

Продукт разрабатывается как веб-приложение, не требующее отдельной установки.

Предварительная конфигурация для проверки компьютерной версии:

- Windows 10 или новее;
- двухъядерный процессор;
- 4 ГБ оперативной памяти;
- браузер Chrome, Edge или Firefox с включённым JavaScript;
- доступ в интернет.

Адаптивность интерфейса будет проверяться на смартфоне с Android и браузером Chrome. Материалы и прогресс будут храниться на сервере и загружаться после входа в аккаунт. 

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Приложение будет предоставлять следующие возможности:

1. Управление аккаунтом: регистрация, вход, выход, изменение данных и восстановление доступа.
2. Добавление учебного материала вставкой текста или загрузкой PDF с текстовым слоем.
3. Просмотр, переименование и удаление собственных материалов.
4. Получение структуры подтем, выделенных из материала.
5. Создание тренировочных заданий с одним правильным вариантом ответа.
6. Прохождение начальной диагностики с указанием уверенности в ответах.
7. Получение объяснения ответа и ссылки на исходный фрагмент материала.
8. Прохождение адаптивной тренировки с дополнительными проверками затруднений и объяснением выбора следующего задания.
9. Сохранение состояния занятия и продолжение после повторного входа.
10. Просмотр истории попыток и прогресса по подтемам.
11. Отправка сообщения о некорректном задании.
12. Просмотр инструкции по использованию приложения.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

Для сравнения выбраны:

- **StudyFetch** — создание учебных материалов, тестов и персонального плана на основе загруженных документов.
- **RemNote** — работа с документами, карточками, тестами и отслеживанием освоения материала.
- **Quizlet** — создание карточек и тренировочных материалов, включая инструменты на основе загруженных заметок.

Отличие MindForge — понятная пользователю адаптация с учётом правильности и уверенности ответов: система должна различать уверенный ответ, сомнение и угадывание, предлагать дополнительные проверки и объяснять их выбор.

Для каждого аналога будет проверено, насколько этот сценарий поддерживается и удобен. Отсутствие функций не будет утверждаться без проверки. Результаты сравнения и выявленные ограничения будут внесены в заявку после испытания сервисов.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]**

- **Python / FastAPI** — серверная часть и обработка запросов.
- **HTML / CSS / JavaScript** — адаптивный интерфейс.
- **PostgreSQL / Psycopg** — хранение аккаунтов, материалов, заданий, ответов и прогресса. Реляционная база выбрана для организации связей между этими данными.
- **API языковой модели** — анализ материалов и подготовка заданий.
- **Библиотека извлечения текста из PDF** — обработка загружаемых документов; конкретный инструмент будет выбран после проверки.
- **Visual Studio Code** — среда разработки.
- **Git / GitHub** — история изменений, код и документация.
- **Docker / GitHub Actions** — контейнеризация, автоматические проверки и развёртывание.

**[ ЭТАПЫ РАЗРАБОТКИ ]**

1. **Ноябрь:**  оформление заявки и размещение в GitHub
2. **Декабрь:** исследование аудитории и аналогов, подготовка пользовательских сценариев и первой версии отчёта.
3. **Декабрь–январь:** разработка обработки материалов, базы данных и начального прототипа.
4. **Февраль:** контроль готовности с экспертом, подготовка объектных и UML-диаграмм для первой волны, первый показ кода до окончательной заявки.
5. **Март:** реализация аккаунтов, генерации заданий, адаптации, истории и интерфейса; публикация первой версии окончательной заявки до 1 апреля
6. **Апрель–начало мая:** второй показ кода, развёртывание, экспертная проверка содержания, пользовательские испытания, сравнение с аналогом и исправления.
7. **До 14 мая:** представление итогового отчёта, демонстрационного видео, исходников и ссылки на приложение.



**[ ВОЗМОЖНЫЕ РИСКИ ]**

- **Недостаток времени на изучение FastAPI, PostgreSQL и разработки интерфейса.** Может задержать завершение продукта. Сначала реализуется полный основной сценарий; изменения объёма согласуются с экспертом.
- **Ошибки в заданиях и объяснениях.** Могут снижать качество подготовки. Предусмотрены привязка к источнику, проверка выборки преподавателями и сообщения пользователей об ошибках.
- **Неточная оценка освоения тем.** Угадывания и единичные ошибки могут искажать результат. Алгоритм будет учитывать несколько ответов и уверенность ученика, а его поведение проверяться на тестовых сценариях.
- **Сбои и расходы внешнего API.** Могут прерывать генерацию. Предусмотрены ограничения запросов, сохранение созданных заданий, прогресса и повтор после сбоя.
